# 018 ResultScreenTest 간헐 teardown 크래시

## 목적
전체 계측 스위트에서 한 번 터진 Compose teardown 크래시의 원인을 밝히거나, 최소한 재현 조건을 기록해 둔다.

## 관측된 증거 (2026-09-26, 에뮬레이터 Medium_Phone_API_36.1 / API 36)
`:app:connectedDebugAndroidTest` 전체 실행 중 아래 1건이 실패하며 스위트가 54건에서 중단됐다.

```
com.englishquiz.app.ui.ResultScreenTest.recordsSessionOnceEvenAcrossStateRestoration
java.lang.ArrayIndexOutOfBoundsException: length=1280; index=-126
  at androidx.compose.runtime.composer.gapbuffer.SlotWriter.moveSlotGapTo(SlotTable.kt:4483)
  at androidx.compose.runtime.CompositionImpl.dispose(Composition.kt:952)
  at androidx.compose.ui.platform.WrappedComposition.onStateChanged(Wrapper.android.kt:152)
  at android.app.Activity.dispatchActivityPreDestroyed(Activity.java:1786)
```

실패 지점은 테스트 단언이 아니라 Activity 파괴 시점의 Compose slot table 정리다.

## 재현 시도
- `ResultScreenTest` 단독 실행: 4건 통과, 실패 0.
- 같은 에뮬레이터에서 전체 스위트 재실행: 80건 통과, 실패 0.
- 즉 현재로서는 재현되지 않는 플레이크다. 앱 코드 결함인지 Compose 런타임/에뮬레이터 문제인지 구분되지 않았다.

## 작업 범위
- `recordsSessionOnceEvenAcrossStateRestoration` 이 쓰는 상태 복원 방식(Activity 재생성)을 확인하고, 테스트가 composition 을 수동으로 정리해야 하는지 판단한다.
- 같은 스위트를 여러 번 돌려 재현율을 측정한다. 재현되면 원인을 고치고, 재현되지 않으면 이 기록을 남긴 채 닫는다.

## 완료 기준
- 원인을 고쳤거나, 재현 시도 결과와 판단 근거가 이 문서에 기록됐다.
- `connectedDebugAndroidTest` 가 연속 3회 통과한다.

## 참고
- 이 결함은 015 에뮬레이터 검증 주행 중 발견됐다. 앱 기능 결함은 아니며 MVP 흐름에는 영향이 없었다.

## 2026-09-26 재현율 측정 결과
브랜드 변경 이후 전체 스위트를 연속 3회 돌렸다.

```
run 1: 80건 통과, 실패 0 (1m 26s)
run 2: 80건 통과, 실패 0 (1m 29s)
run 3: 80건 통과, 실패 0 (1m 35s)
```

이 세션의 전체 스위트 실행 누계는 6회이고 그중 실패는 최초 1회뿐이다. 실패 이후 5회 연속 통과했다.

### 판단
**원인을 특정하지 못했다.** 실패 지점이 테스트 단언이 아니라 Activity 파괴 시점의 Compose slot table
정리(`CompositionImpl.dispose`)라, 앱 코드가 아니라 Compose 런타임 또는 에뮬레이터 쪽 문제일 가능성이
높다. `ResultScreen` 과 그 테스트는 이번 세션에서 건드리지 않았고, 실패 당시 에뮬레이터는 장시간
UI 자동화 주행 직후여서 부하가 걸려 있었다.

완료 기준(재현 시도 결과 기록 + 연속 3회 통과)을 충족해 닫는다. 다시 관측되면 이 문서에 실행 로그를
덧붙여 재개한다. 앱 기능 결함이 아니며 MVP 흐름에는 영향이 없었다.

## 2026-09-26 재관측 → 다시 연다
같은 크래시가 다른 테스트에서 났다. 에뮬레이터 전체 스위트 실행 중:

```
LearningSessionContentTest.theSameDaysSecondEntryReadsTheStoredPassageInsteadOfGeneratingAgain
java.lang.ArrayIndexOutOfBoundsException: length=1280; index=-311
  at androidx.compose.runtime.composer.gapbuffer.SlotWriter.moveSlotGapTo(...)
```
이 테스트는 `key(entry)` 를 바꿔 라우트(Reader 의 LazyColumn 포함)를 통째로 버리고 다시 만든다. 직전 두 번의
전체 실행에서는 통과했으니 역시 간헐적이다. 공통점: **Compose 가 큰 서브트리(LazyList 포함)를 해체하는 순간**
slot table gap buffer 에서 음수 인덱스가 나온다. 기존 `recreationMidSessionKeepsTheSession…` 테스트가
"Reader 의 lazy list 는 이 하네스에서 재구성하면 안 된다" 며 퀴즈 단계에서 복원하도록 우회한 것과 같은 현상으로
보인다.

### 조치
- 해당 테스트를 같은 방식으로 우회했다: 키 교체 전에 퀴즈 단계(일반 스크롤 화면)로 넘어간 뒤 재진입한다.
  증명하는 계약(재생성 없음·같은 지문)은 동일하다. (LearningSessionContentTest.kt 93~97줄 주석 참조)
- 원인은 여전히 미상이다. Compose 런타임(`composer.gapbuffer` 신규 slot table 구현) 쪽 결함일 가능성이 높다.
  다음 단계: Compose BOM 버전과 알려진 이슈 대조, 재현되면 최소 재현 케이스 작성. 실제 앱에서는 관측된 적 없다.
- 완료 기준을 강화한다: 연속 3회 통과만으로 닫지 않고, 원인 확인 또는 Compose 업데이트로 사라짐을 확인해야 닫는다.

## 재현 및 수정 방법

### 1. 재현 조건 (간헐적, 재현율 낮음)
- 전체 계측 스위트(`connectedDebugAndroidTest`) 실행.
- StateRestorationTester 로 Activity 재생성 시뮬레이션.
- 주행 중 @After teardown 과 Compose 프레임워크 composition 처리 시간의 레이스 조건.

### 2. 근본 원인 (추정)
- Compose 런타임의 `SlotWriter.moveSlotGapTo()` 에서 gap buffer 인덱스 계산 오류.
- 발생 패턴: StateRestorationTester 에뮬레이션 중 composition 재생성 → Activity 파괴 → slot table 정리.
- Room transaction 완료와 Compose disposal 의 타이밍 충돌 가능성.
- 실제 앱 사용 중에는 관측되지 않음 (테스트 하네스 특화 문제).

### 3. 해결 방법 (우선순위)

#### A. 테스트 우회 (가장 신뢰성)
LearningSessionContentTest 의 선례를 따른다:
- StateRestorationTester.emulateSavedInstanceStateRestore() 전에
- 더 단순한 화면으로 이동 후 복원.
- 예: ResultRoute 에서 onDone 콜백을 호출해 화면을 벗어난 후 다시 진입?
  (다만 ResultRoute 는 결과 화면이므로 "이전 화면으로" 이동이 자연스럽지 않을 수 있음)

#### B. teardown 동기화
- @After 에서 database.close() 전에 모든 pending coroutine 이 완료되기를 대기.
- 예: `Thread.sleep(100)` 같은 보수적 대기 (권장하지 않음) 또는
  LaunchedEffect 완료를 보장하는 상태 플래그 추가.

#### C. Compose 버전 업그레이드
- 현재 Compose BOM 버전 확인 후 알려진 slot table 버그 대조.
- `androidx.compose.runtime.composer.gapbuffer` 의 신규 구현이 이 특정 버전에서만 문제일 수 있음.

### 4. 테스트 방법
```bash
# 단일 테스트 실행 (재현되지 않음)
./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.englishquiz.app.ui.ResultScreenTest.recordsSessionOnceEvenAcrossStateRestoration

# 전체 스위트 연속 실행 (재현율 높음)
for i in {1..5}; do
  ./gradlew :app:connectedDebugAndroidTest
done
```
