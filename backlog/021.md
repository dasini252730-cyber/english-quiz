# 021 오늘의 콘텐츠 생성 지연과 매번 재생성 문제

## 목적
사용자가 실기기 사용 중 지적(2026-09-26): Conversation/Story 를 탭할 때마다 AI 가 새 콘텐츠를 만들어 30초 안팎 기다려야 하고, 같은 날 다시 들어가도 또 새로 만든다. 요구사항의 '오늘의 학습' 의미에 맞게 하루 단위 콘텐츠 보관/재사용 정책을 정하고, 생성 지연을 줄이는 계획(모델·출력 크기·선생성)을 세워 구현한다.

## 작업 범위

**1단계 (핵심): 일일 콘텐츠 캐싱**
- Room 마이그레이션 v3→v4: `daily_content` 테이블 (`learningDate`, `mode` 복합 고유키)
- `DailyContentEntity`: learningDate, mode, conversationJson/storyJson, expressionList, createdAt
- `LearningRepository.findTodayContent(mode: String): DailyContent?`
- `LearningRepository.saveTodayContent(mode: String, content: DailyContent): Unit`
- `LearningSessionRoute`: 진입 시 오늘 콘텐츠 조회 → 존재하면 사용, 없으면 생성 후 저장
- "다시 시도" (생성 실패): 즉시 재생성 (캐시 무시)
- 마이그레이션 테스트 추가: 기존 세션 레코드 보존 확인

**2단계 (선택): 모델 최적화**
- Supabase 시크릿에 `ANTHROPIC_MODEL=claude-haiku-4-5-20251001` 설정 (코드 변경 없음)
- 실측으로 생성 시간 단축 확인 (Conversation 목표 ~10초, Story ~15초)

**3단계 (보류): 선생성**
- 세션 종료/퇴장 후 내일 콘텐츠 비동기 생성
- 1·2단계 후 여전히 느리면 고려 (앱 시작 지연 방지 필수)

## 완료 기준

- **같은 날 재진입**: LearningSessionRoute 재진입 시 0초 내 기존 콘텐츠 표시 (DB 쿼리만)
- **앱 재시작 보존**: 앱 재시작 후에도 같은 날 콘텐츠 동일 (Room 지속성)
- **다음 날 새로 생성**: learningDate 변경 시 새 콘텐츠 자동 생성
- **마이그레이션 안전성**: 기존 LearningSessionEntity/SavedExpressionEntity 데이터 무손실 (마이그레이션 테스트 통과)
- **계측 테스트**: findTodayContent/saveTodayContent 단위 테스트 (정상·오류 케이스)
- **실측 지연 기록**: 같은 날 재진입 0초, Conversation 생성 ~10초, Story 생성 ~15초 (모델 최적화 후)

## 구현 순서

### 1단계: 스키마·엔티티·마이그레이션
1. `DailyContentEntity.kt` 정의 (`learningDate`, `mode`, 복합 고유키)
2. `LearningDatabase.kt` v4 마이그레이션 생성 (v3→v4, daily_content 테이블 생성)
3. `app/schemas/4.json` 스냅샷 갱신
4. `LearningDatabaseMigrationTest.kt` 추가: v3→v4 전후 데이터 검증

### 2단계: Repository 메서드
1. `LearningRepository.findTodayContent(mode: String): DailyContent?` 구현
   - 오늘 learningDate, 주어진 mode로 daily_content 테이블 조회
   - null 시 미캐시 신호
2. `LearningRepository.saveTodayContent(mode: String, content: DailyContent): Unit` 구현
   - (learningDate, mode, 생성된 지문, 메타데이터) 저장

### 3단계: LearningSessionRoute 로직
1. generateContent 전에 `repository.findTodayContent(mode)` 호출
2. 결과 있음 → 기존 콘텐츠 사용
3. 결과 없음 → 생성, `repository.saveTodayContent(mode, result)` 저장
4. 생성 실패 후 재시도 → 캐시 무시, 즉시 재생성
5. SessionStepSaver: 세션 직렬화에 오늘 콘텐츠 ID 포함 (옵션)

### 4단계: 테스트 및 검증
1. 단위 테스트: findTodayContent/saveTodayContent 정상·오류·중복 케이스
2. 통합 테스트: LearningSessionRoute 진입→생성→저장→재진입 검증
3. 마이그레이션 테스트: v3→v4 무손실성
4. 수동 실측:
   - 같은 날 같은 모드 재진입 (응답 시간 0초)
   - 앱 재시작 (콘텐츠 유지)
   - 다음 날 진입 (새로 생성)

### 2단계(후순): 모델 최적화 (선택)
- Supabase 시크릿 `ANTHROPIC_MODEL=claude-haiku-4-5-20251001` 설정
- 실측 재검증 (Conversation ~10초, Story ~15초 목표)

### 리뷰(code-critic)가 잡은 것과 처리
1. **캐시가 간격 반복을 망가뜨릴 수 있었다(높음).** `QuizBuilder` 가 오늘 지문에 나오는 저장 표현을 기한과
   무관하게 출제 후보에 합쳐서, 같은 지문을 다시 읽고 퀴즈를 풀면 하루에 복습 일정이 여러 번 앞당겨져
   "암기 완료"까지 갈 수 있었다. 021 전에는 지문이 매번 달라 드러나지 않던 잠재 결함. 후보를 due 로만
   한정해 고쳤고 `QuizBuilderTest` 로 고정했다. 이제 같은 날 재진입의 퀴즈는 새로 저장한 표현이 없으면
   "오늘 복습할 표현이 없어요" 로 끝나며 복습 상태를 건드리지 않는다.
2. `zoneId` 를 결과 화면까지 넘겨 캐시 키와 세션/스트릭 날짜가 같은 규칙을 쓰게 했다.
3. `difficulty` 컬럼은 읽는 곳이 없어 제거했다(v4 배포 전이라 v5 불필요). 난이도 변경(013)은
   요구사항 8절대로 "다음 콘텐츠 생성", 즉 다음 날부터 반영된다. 같은 날 보관본은 생성 당시 난이도.

### 문서와 코드가 달랐던 점 정리
- "다시 시도"는 캐시를 먼저 본다. 생성이 실패했으면 오늘 행이 없어 어차피 생성하고, DB 오류로 실패한
  경우엔 재시도에서 보관본을 읽는 편이 낫다. 위 1단계 계획의 "재시도는 항상 재생성" 문구는 이걸로 대체.
- 성능 목표 "Conversation ~10초"는 실측 12.2초로 마감한다. 남은 지연은 모델 출력 길이(요구사항 10.2 의
  10분 분량) 때문이며, 같은 날 재진입이 0초가 되어 체감 대기는 하루 모드당 한 번뿐이다.
- 같은 날 재진입은 `learning_sessions` 에 0문항 세션 행을 하나 더 남긴다. `DifficultyPolicy` 는 0문항을
  제외하고 스트릭은 날짜 단위라 영향 없다.
- **주의**: `difficulty` 컬럼이 있던 중간 v4 빌드가 에뮬레이터에만 잠깐 설치됐었다. 같은 버전 번호에
  스키마가 달라 Room 이 무결성 오류를 내므로 `pm clear` 로 지웠다. 폰은 v3 → 정상 마이그레이션.
