# 010 오늘의 퀴즈

## 목적
콘텐츠 학습 후 약 10분 동안 오늘의 표현과 복습 기한이 된 표현을 확인한다.

## 작업 범위
- 오늘 콘텐츠의 복습 표현, 오늘 새로 저장한 표현, 복습일이 된 기존 표현을 모은다.
- 객관식 뜻 선택 및 문맥 빈칸 문제를 제공한다.
- 진행률, 정오답, 간단한 설명과 다음 문제 이동을 구현한다.
- 같은 세션의 문제 중복과 빈 문제 세트를 처리한다.

## 완료 기준
- 오늘 콘텐츠에 나오지 않은 기한 도래 표현도 출제될 수 있다.
- 각 답변 결과가 학습 기록에 전달된다.
- 퀴즈 완료 시 결과 화면으로 이어진다.

## 2026-09-24 적대적 리뷰 반영 (오답 보기)

### 고친 것 — 같은 표현이 정답과 오답으로 동시에 나올 수 있었다
`normalize()` 가 trim + lowercase + 공백 정리만 해서, 이번에 같은 풀에 섞이게 된 두 출처의 문자열
차이를 흡수하지 못했다.
- 저장된 표현: Reader 가 지문 원문에서 잘라낸 문자열에서 가장자리 구두점을 제거한 것 (`ReaderTokens`).
  지문이 컬리 어포스트로피를 쓰면 그대로 남는다.
- 콘텐츠 주석: 모델이 보낸 문자열을 trim 만 한 것. 서버는 offset 만 folded 공간에서 계산하고 `text`
  자체는 접지 않는다. 애초에 `foldTypography` 가 존재한다는 것이 "모델은 스트레이트, 지문은 컬리" 가
  실제로 일어난다는 뜻이다.

그래서 `I’m all ears`(저장)와 `I'm all ears`(주석)가 서로 다른 것으로 취급돼, **화면상 구분되지
않는 두 보기가 하나는 정답, 하나는 오답으로 함께 제시될 수 있었다.** 학습자가 오답 쪽을 누르면
`recordAnswer` 가 오답으로 기록하고 복습 간격과 정답률까지 틀어진다. 사용자 데이터가 잘못 기록되는
경로라 심각도가 높다.

- `normalize()` 가 `foldTypography()` 로 접고 가장자리 구두점을 제거한 뒤 비교하도록 바꿨다. Reader 가
  저장 시 떼는 것과 같은 구두점 집합을 쓴다.
- 보기 텍스트 비교도 원문 `equals` 대신 `normalize` 를 쓴다. 뜻이 `그만하다` 와 `그만하다.` 로 갈리는
  경우도 같은 문제였다.
- 부수 효과로 `matchContentReviewExpressions` 도 고쳐졌다. 컬리 어포스트로피가 섞인 표현을 "오늘
  콘텐츠의 복습 표현"(요구사항 14.1)으로 인식하지 못하던 기존 결함이다.

- `aWrongOptionThatOnlyDiffersByTrailingPunctuationIsRejected`

  문항 타입을 단언한다.
- 앞의 두 테스트는 수정 전 코드에서 실제로 실패하는 것을 확인했다(가짜 통과가 아님).

### 추가로 고친 것 — 길이만 보고 정답을 고를 수 있었다
리뷰가 "정답 뜻과 오답 뜻이 서로 다른 프롬프트에서 온다"고 지적해 배포된 함수로 실측했다.

```
오답 출처(content 액션):  8~19자   "한번 시도해보다" / "마음을 정하다, 결정하다"
정답 출처(meaning 액션):  73자     "어려운 일을 성공적으로 해내다, 성사시키다라는 뜻입니다. 여기서는 ..."
```

문체가 확연히 다르다. 뜻 고르기 문항에서 **표현을 전혀 몰라도 가장 긴 보기를 고르면 항상 정답**이
된다. 원래는 모든 보기가 저장 표현(= 같은 meaning 액션)에서 나와 문체가 일관됐는데, 지문 표현을
보기로 끌어오면서 이 성질이 깨졌다. 즉 이번 변경이 만든 결함이다.

- 지문 표현은 **빈칸 문항의 보기로만** 쓴다. 빈칸 문항의 보기는 표현 텍스트라 길이 단서가 없다.
- 뜻 고르기 문항은 저장 표현에서만 보기를 뽑는다. `Distractor` 에 출처(`fromSaved`)를 실었다.
- 첫 세션의 저장 표현은 Reader 가 문맥 문장을 함께 저장하므로 항상 빈칸 문항이 만들어진다. 따라서
  원래 고치려던 "첫 세션 빈 퀴즈" 는 그대로 해결된 상태다. 주행으로 확인했다(1회차 퀴즈 2문항).
- 프롬프트를 맞추는 대신 출처를 제한한 이유: meaning 액션의 긴 설명은 Reader 오버레이에서 학습자가
  실제로 읽는 문구라 짧게 줄이면 요구사항 11 의 문맥 설명이 얕아진다. content 액션의 짧은 구는
