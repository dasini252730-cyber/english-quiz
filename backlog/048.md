## 목적

## 구현 메모 (2026-10-07)

- **due vs never 분할**: `todayExpressions.partition { it.lastReviewedAtEpochMillis != null }`
- **정렬 유지**: due 그룹도 nextReviewAtEpochMillis 순서 유지 (originalOrder 손상 없음). `due.sortedWith(compareBy({ it.nextReviewAtEpochMillis ?: it.firstSavedAtEpochMillis }, { it.id }))`
- **선택 로직**: 
  ```
  val selectedDue = due.take(maxQuestions)
  val remainingSlots = maxQuestions - selectedDue.size
  val selectedNever = never.take(minOf(remainingSlots, NEW_PER_DAY))
  val selected = (selectedDue + selectedNever).shuffled(random)
  ```
- **테스트 케이스**:
  1. `newExpressionsAreCappedAtFivePerQuiz`: due 5개 + new 15개 → 10개만 출력 (due 5 + new 5)
  2. `dueExpressionsFillTheQuizFirst`: due 10개 + new 10개, maxQuestions = 10 → 10개 모두 due (new 없음)
  3. `newCapDoesNotIncreaseWhenMaxQuestionsRaises`: maxQuestions = 15인데 due 5개 + new 15개 → 10개 선택 (due 5 + new 5)
  4. `librarySessionIgnoresNewCap`: library 다시 읽기는 표현을 묻지 않으므로 cap 무관
