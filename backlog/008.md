# 008 문맥 표현 뜻과 자동 저장

## 목적
모르는 표현을 콘텐츠에서 바로 확인하고 별도 저장 버튼 없이 복습 대상으로 만든다.

## 작업 범위
- 문장 내 단어 또는 표현 선택 영역을 제공한다.
- 문맥상 의미를 표시하고 필요하면 AI 설명을 요청한다.
- 뜻 조회 성공 시 표현, 문맥, 의미, 최초 저장일을 로컬 저장소에 upsert한다.
- 발음 재생과 저장 완료 피드백을 제공한다.
- overlay 닫기 후 Reader 위치를 보존한다.

## 완료 기준
- 뜻은 사전 번역보다 현재 문맥 의미를 우선한다.
- 조회 실패 시 저장 완료로 오인시키지 않고 재시도/오류를 안내한다.
- 이미 있는 표현 선택 시 기존 복습 상태와 최초 저장일이 유지된다.

## 확정된 구현 결정 (2026-09-20, 메인)
- 선택 방식은 **탭(터치)** 이다. 요구사항 11절이 "모르는 단어나 표현을 터치할 수 있다"로 규정하므로 길게 누르기나 문자 드래그 선택은 쓰지 않는다.
- 세그먼트 본문은 `FlowRow` 기반 토큰으로 그린다. AI가 준 `ContentExpression`의 `startIndex..endIndex` 범위는 하나의 토큰으로 묶고 나머지는 단어 단위로 자른다. 토큰마다 독립 semantics 노드가 생겨 Compose 테스트에서 표현 단위 탭을 직접 증명할 수 있기 때문이다.
- ViewModel을 새로 도입하지 않는다. `ReaderRoute`/`ReviewRoute`가 이미 쓰는 `remember` + `produceState` + `rememberCoroutineScope` 패턴을 따른다.
- `MeaningRequest.context`에는 표현이 속한 세그먼트 문장 전체를 넣는다.
- 뜻 조회가 실패하면 저장하지 않고 오버레이에 오류와 재시도를 표시한다. 저장 완료 피드백은 저장이 끝난 뒤에만 노출한다.
- 저장 스키마: `SavedExpressionEntity.contextSentence` 칼럼을 메인이 추가했다(DB v3, `MIGRATION_2_3`). `LearningRepository.saveExpression(displayExpression, contextMeaning, savedAtEpochMillis, contextSentence)`에 문맥 문장을 함께 넘긴다. 요구사항 12절의 최초 저장일·복습 상태 보존은 기존 `INSERT OR IGNORE` 동작이 그대로 책임진다.

완료 기준 대조:
- **뜻은 사전 번역보다 현재 문맥 의미를 우선한다** — `explainMeaningReceivesFullSentenceAndSavesSameSentenceAsContext`
  가 표현이 속한 문장 전체를 요청에 넣고 같은 문장을 문맥으로 저장하는 것을 단언한다. Edge Function 의
  system prompt 도 "in its supplied sentence" 로 고정돼 있다. 실호출에서 'I've' 를 눌렀을 때 "'I have'의
  축약형으로, 여기서는 현재완료 시제(have been)를 만들기 위해 사용됨" 이 나온 것으로 실제 동작을 확인했다.
- **조회 실패 시 저장 완료로 오인시키지 않고 재시도/오류를 안내한다** — `lookupFailureShowsRetryWithoutClaimingItWasSaved`,
  `saveFailureShowsRetryAndRetryOnlyRetriesSaveNotTheAiCall`(재시도가 유료 호출을 반복하지 않는 것까지).
- **이미 있는 표현 선택 시 기존 복습 상태와 최초 저장일이 유지된다** — `duplicateExpressionKeepsFirstSavedDateAndReviewState`
  및 `duplicateExpressionKeepsExistingReviewStateAfterDatabaseReopen`(재실행 후에도 유지).
