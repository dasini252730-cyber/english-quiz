# 066 중국어 확장 (에픽): 언어 전환, 데이터 분리, 중국어 생성·병음·TTS·채점

## 목적
기존 영어 기능을 그대로 두고 중국어(중국 본토 표준어, 간체자) 학습을 추가한다. 홈에서 English / 中文을 전환하고, 지문·시즌·저장 표현·퀴즈 기록·복습 상태·난이도를 언어별로 분리한다. 별도 앱·학습 엔진·다국어 프레임워크·로그인·동기화·구독은 만들지 않는다. 사용자 요청 2026-10-17.

## 현황 조사 결과 (2026-10-17)
언어 개념이 코드 어디에도 없다. 축은 `ContentMode`(conversation/story)와 난이도 1~5뿐이고, 영어는 다음 지점에 암묵적으로 박혀 있다.

| 영역 | 영어 고정 지점 |
|---|---|
| Room (v11) | `daily_content` PK `(learningDate, mode)`; `saved_expressions` 유니크 `normalizedExpression`; `seasons` 유니크 `number`; `season_episodes`·`learning_sessions`에 언어 없음. 전 테이블 조회가 전역 (`findDueExpressions`, `listBossCandidates`, `oldestUnread`, `episodeReadOn` 등) |
| DataStore | `level_<mode>`, `sessions_since_level_change_<mode>`, `suggested_level_<mode>`, `last_counted_session_<mode>` — 모드만 키 |
| 서버 요청 | `action/mode/difficulty/reviewExpressions/previousStory/companion/season`에 언어 필드 없음. 프롬프트가 영어 전제 |
| TTS | `SpeechEngine.kt` `Locale.US` 고정, 보이스 필터 `language == "en"`, `SpeakerVoices` 성별 마커가 영어 보이스 이름 규칙 |
| 리더 | `ReaderTokens` 공백 기준 토큰화, `ReaderSegments` FlowRow가 토큰 사이 4dp 공백 재삽입, 가장자리 문장부호가 ASCII만 |
| 퀴즈 채점 | `QuizText.kt` 전체가 영어 전용(축약형, 어미 변화 `stem()`, 불규칙 과거 70개, 첫 글자 힌트), `normalizeExpression`은 lowercase+공백 정리 |
| 진단 | `AssessmentQuestion` 8문항이 영어 콘텐츠 |
| 문구 | "오늘의 영어 학습", "영어 표현 입력", "이 뜻의 영어 표현을…", "영어 음성을 사용할 수 없어요" |

스트릭·점수·배지·미션은 테이블이 없고 `listAllSessions`+`listSavedExpressions`에서 매번 계산된다. 이 두 조회에 언어 필터를 걸지 않으면 스트릭은 공유, 걸면 분리된다.

## 설계 원칙
- `Language` enum(`en`/`zh`) 하나를 `ContentMode`와 같은 방식으로 저장·요청·조회에 끼운다. 영어 기존 행은 전부 `'en'` 기본값으로 보존한다.
- 서버 요청에 `language`를 추가하되 기본값 `en`이라 구 APK와 호환된다(서버 먼저 배포).
- 언어별로 달라지는 것(토큰화, 채점, 정규화, TTS 로케일, 프롬프트 규칙)은 `when (language)` 분기 또는 언어별 작은 파일로 두고, 공통 흐름(세션 → 리더 → 퀴즈 → 결과 → 복습)은 건드리지 않는다.
- 영어 코드 리팩터링은 언어 파라미터를 끼우는 최소 수준으로만 한다.

## 결정 사항 (2026-10-18 사용자가 추천안 승인: 1·2·3 모두 권장안으로 확정)
1. **스트릭·점수·배지·미션은 두 언어 공유** (권장). 하루에 어느 언어든 학습하면 스트릭 유지. 저장 표현 수·암기 완료 수는 선택 언어 기준으로 표시.
2. **선생성(프리페치)은 선택된 언어만** (권장). 두 언어를 매일 밤 다 만들면 생성 호출이 2배(하루 상한 40 공유).
3. **병음 표시**: 표현·용어집·퀴즈 카드에는 항상 표시. 지문 각 줄의 병음(글자 위)은 리더 상단 토글(기본 꺼짐, 화면 상태로 유지 — 설정 저장은 보류, 071 결정).
4. **중국어 진단 없음**: 요구대로 초기 레벨 3(대화·스토리). 영어 진단 화면은 그대로.
5. **라이브러리·복습함은 선택 언어만 표시**.
6. 중국어 대화 배경은 중국어권 여행지(본토 도시 중심). 스토리 시즌 주제 목록은 공유하되 시즌·인물·사건은 언어별 독립.

## 변경 계획

### A. 언어 모델과 설정 (앱)
- `data/ai/Language.kt`: `enum class Language(val wireValue: String, val locale: Locale) { ENGLISH("en", Locale.US), CHINESE("zh", Locale.SIMPLIFIED_CHINESE) }`.
- `AppSettingsRepository`: `selected_language` 키(기본 `en`). 레벨 키는 영어는 기존 그대로(`level_story`), 중국어는 `level_zh_story`처럼 접미사. `AppSettings.levels: Map<Pair<Language, ContentMode>, ModeLevel>`, `level(language, mode)`. 중국어 기본 레벨 3. `applyFinishedSession`·`acceptSuggestion`·`dismissSuggestion`에 language 파라미터. DataStore 마이그레이션 불필요.
- 홈(`HomeScreen`/`HomeSummaryRoute`): 상단 English / 中文 세그먼트 버튼. 선택 언어가 세션·퀴즈·복습함·라이브러리·시즌 라벨·레벨 표시에 흐른다. 제목 "오늘의 영어 학습" → 언어별 문구.

### B. Room v12 (`MIGRATION_11_12`)
| 테이블 | 변경 | 마이그레이션 |
|---|---|---|
| `daily_content` | PK `(language, learningDate, mode)` | 재생성 후 복사(1→2 방식), 기존 행 `'en'` |
| `saved_expressions` | `language TEXT NOT NULL DEFAULT 'en'`, `pinyin TEXT NOT NULL DEFAULT ''`; 유니크 인덱스를 `(language, normalizedExpression)`로 | ADD COLUMN 2개, 인덱스 DROP/CREATE |
| `learning_sessions` | `language` 추가 | ADD COLUMN |
| `seasons` | `language` 추가, 유니크 `(language, number)` | ADD COLUMN, 인덱스 교체 |
| `season_episodes` | `language` 추가(비정규화, 조인 없이 조회) | ADD COLUMN |
| `quiz_answers` | 변경 없음(expressionId로 언어 결정) | — |
- DAO: 표현·지문·세션·시즌 조회에 `language` 조건 추가. `listAllSessions`·`listLearningDates`는 그대로(스트릭 공유, 결정 1). `listSavedExpressions`는 언어 필터 버전과 전체 버전 둘 다 둬서 게임 점수는 전체, 홈 타일은 선택 언어.
- `LearningRepository`: 표현·지문·세션 함수에 `language` 파라미터. `normalizeExpression(language, text)`: zh는 공백·문장부호 제거(소문자화 없음).
- `SeasonCoordinator`: `language`를 받아 시즌·회차·companion 조회를 언어별로. `SeasonPolicy.nextEpisode`는 그대로.
- `ContentPrefetcher`: 선택 언어만(결정 2).
- 계측 테스트: `LearningDatabaseMigrationTest` 11→12(기존 영어 행 보존, 유니크 인덱스 교체), 리포지토리 언어 분리 테스트.

### C. Edge Function
- 요청 `language?: "en" | "zh"`(기본 en) — content/season/meaning 모두. 응답 스키마에 `pinyin`(expressions 필수 for zh, segments·glossary 선택) 추가. en 요청에는 영향 없음.
- `chinese-rules.ts`: 중국어 전용 고정 블록(캐시 접두에 포함). 간체자·보통화, 레벨별 문장 길이·어휘(HSK 3~5 감각)·성어 사용 제한, 양사·어기조사 자연스러움, 중국어권 배경, 병음은 성조 부호 표기(nǐ hǎo), `expressions`는 2~6자 어구 중심. 공통 재미 지침(`STORY_RULES`, `SEASON_PLAN_RULES`)은 공유.
- 계약: zh 지문은 `passage_not_chinese`(한자 비율) 검사, 한국어 거부 검사는 그대로. 표현 오프셋 계산(`foldTypography`)은 1:1 매핑이라 한자에 그대로 적용됨.
- 시즌 설계도: `language`를 받아 중국어 시즌을 따로 설계. 설계도 JSON은 서버·앱 모두 언어 무관 구조.
- 테스트: zh 프롬프트 구성, 병음 스키마, 한자 비율 거부, en 요청 불변.

### D. 리더·TTS
- `ReaderTokens.tokenize(language, …)`: zh는 표시 어구(annotated span) → 용어집 단어 최장 일치 → 나머지는 글자 단위. `ReaderSegments`: zh일 때 토큰 간격 0dp. 가장자리 문장부호에 CJK(。，！？、：；“”‘’（）《》) 추가. 오른쪽 화자 "我" 추가.
- 병음: `MeaningOverlay`·퀴즈 학습 카드에 표현 병음, 리더 줄 병음 토글(결정 3).
- `SpeechEngine`/`ReaderSpeech`: 언어 파라미터, `Locale.SIMPLIFIED_CHINESE`, 보이스 필터 `language == "zh"`. `SpeakerVoices` 성별 마커는 보이스 이름에 없으면 기존 피치 폴백. 음성 없음 안내는 "중국어 음성을 사용할 수 없어요. 설정 > TTS에서 중국어 음성을 설치해 주세요." (기기 보이스 유무는 S26 실기 확인 필요)
- 세 `ReaderSpeech` 소유자(리더·퀴즈 카드·복습함)에 언어 전달.

### E. 퀴즈·복습
- `QuizText`: `typedAnswerMatches(language, …)`. zh는 공백·문장부호 제거 후 간체자 완전 일치. 힌트는 첫 글자 + 글자 수만큼 `○`("打○○"). en 경로는 변경 없음.
- `QuizOptions`·`QuizLoader`·`ReviewQueue`·보스 후보: 선택 언어 표현만.
- 문구: "이 뜻의 중국어 표현을 직접 입력하세요", "중국어 표현 입력". 키보드는 언어 무관.
- 복습 일정·숙달 규칙·점수 규칙은 그대로(언어별 행이 자연히 분리됨).

### F. 검증·문서
- 회귀: node 테스트 전체, JVM 단위 테스트 전체, Gradle lint/assembleDebug, 계측 테스트(에뮬레이터: 마이그레이션·리포지토리·리더 토큰; S26: zh TTS·입력).
- 중국어: 생성(서버 테스트+실호출 1회), 병음 표시, TTS, 표현 저장·중복 처리, 퀴즈 채점, 복습 큐.
- 문서: `요구사항/요구사항.md`에 "26. 중국어 확장" 절, `구현기능 명세서.md` 갱신, README 한 줄.

## 위험
- S26에 zh-CN TTS 보이스가 없을 수 있음(설치 안내로 대응, 실기 확인 전까지 4번은 waiting 가능).

## 완료 기준
- 홈에서 언어 전환이 저장되고, 각 언어의 지문·시즌·표현·퀴즈·복습·난이도가 서로 섞이지 않는다.
- 기존 영어 데이터가 마이그레이션 후 그대로 보이고 영어 회귀 테스트가 통과한다.
- 중국어 지문이 간체자로 생성되고 표현마다 병음·한국어 뜻이 있으며, TTS가 zh-CN으로 읽고, 간체자 입력이 채점된다.
