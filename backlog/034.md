# 034 대화/스토리 모드별 5단계 레벨 + 직접 조정

## 결정 (2026-09-30, 사용자 선택: "모드별 5단계 + 내가 직접 조정")
- 대화와 스토리가 각각 1~5 레벨을 가진다. 홈의 모드 카드에 "레벨 N / 5"와 −/+ 버튼. 누르면 즉시 반영.
- 자동 조정(013)은 강제로 바꾸지 않는다. 정책이 다른 레벨을 권하면 카드 아래 "최근 결과를 보니 레벨 N로 올려/낮춰볼까요?
  [레벨 N] [유지]" 제안만 띄우고 사용자가 답한다. 유지를 누르면 다음 제안까지 세션 창(3회)이 다시 채워져야 한다.
- 레벨 테스트(초급/중급/고급 = 1/2/3)는 두 모드 공통 시작 레벨 2/3/4로 매핑(`DifficultyPolicy.initialLevel`).
  양쪽으로 움직일 여지를 남기기 위해서.
- 기존 설치(034 이전, `current_difficulty` 1~3만 저장)는 그 값을 시작 레벨로 읽어 두 모드에 적용 - 재진단 불필요.

## 변경
- `AppSettingsRepository`: `AppSettings(levels: Map<ContentMode, ModeLevel(level, sessionsSinceChange, suggestedLevel)>)`,
  `setLevel`, `acceptSuggestion`, `dismissSuggestion`, `applyFinishedSession(mode, …)` - 제안만 저장.
- Room v5 `MIGRATION_4_5`: `learning_sessions.mode` 컬럼(이전 세션은 ''로 남고 모드별 창에서 제외).
  `listRecentSessionSummaries(mode, limit)`, `ResultRoute(mode)`.
- `DifficultyPolicy.MAX_DIFFICULTY = 5`, `initialLevel()`.
- 홈: `HomeModeCard.kt`(새 파일) - 레벨 행, ± 버튼(끝 레벨에서는 비활성), 제안 답변 칩. 카드 탭과 분리.
  `HomeRoute`가 `AppSettings`를 받아 모드별 레벨을 세션에 넘기고, 세션 기록 훅이 모드를 함께 전달.
- `EnglishQuizApp`: `suggestLevel(mode)` - 정책 결과를 제안으로 저장. 레벨 변경/제안 답변은 DataStore에 바로 기록.
- 프리페치: 내일 지문을 모드별 레벨로 생성.
- 서버: `Difficulty = 1..5`, `difficultyRubric` 5단계(1 starter … 5 advanced). 배포 완료(034 이전 앱의 1~3도 그대로 유효).

## 리뷰(code-critic) 반영
- 끝 레벨에서 비활성인 ± 버튼이 탭을 카드로 흘려 세션을 시작시키던 문제: clickable은 항상 켜 두고 시맨틱만 disabled.
- 정책이 "유지"로 돌아서면 답하지 않은 옛 제안을 지운다(낡은 근거로 수락되는 일 방지). 세션 중복 방지 키는 모드별.
- 라이브러리 다시 읽기 세션은 `mode = "library"`로 기록하고 어떤 모드의 제안 창에도 들어가지 않는다(022 해소).
  `LearningSessionEntity.mode`에 `@ColumnInfo(defaultValue = "''")`로 신규 설치 스키마와 마이그레이션 일치.
- `LearningRepositoryTest`: 모드별 창이 다른 모드·재읽기·모드 없는 옛 세션을 제외하고 최신순임을 증명.
- 요구사항.md 8절/17절을 "자동 조절" → "제안 + 직접 조정"으로 개정 기록(사용자 결정 2026-09-30).
