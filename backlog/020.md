# 020 대화 화자별 남/여 목소리 구분

## 목적
Conversation 모드에서 두 화자(예: Anna/Tom)가 같은 TTS 기본 음성으로 읽혀 구분이 안 된다. 사용자가 실기기 사용 중 요청했다(2026-09-26). 화자별로 성별이 다른 음성을 배정하고, 기기에 그런 음성이 없으면 최소한 피치를 다르게 해 구분되게 한다. 요구사항 13장(TTS)의 확장.

## 작업 범위

1. **SpeakerVoices** (JVM 테스트): 화자 이름 또는 성별 힌트 → 기기 가용 음성/피치 배정 (Google TTS 기본, Samsung 커스텀 음성 고려)
2. **SpeechLine(text, speaker)** 또는 SpeechRequest 타입: 텍스트와 화자를 함께 전달
3. **SpeechEngine 확장**: setVoice, setPitch 메서드 추가
4. **ReaderSpeech.play 확장**: SpeechLine 리스트 처리, 화자 변경 시 음성/피치 적용
5. **ReaderScreen/ReaderSegments**: onPlay 콜백 및 호출 방식 조정 (화자 정보 포함)
6. **테스트 강화**: 
   - RecordingEngine에 음성/피치 추적 추가
   - 화자별 음성 일관성 검증 (같은 화자는 같은 음성)
   - 두 화자가 다른 음성/피치로 재생됨 증명

## 완료 기준

1. **기능**: 대화 모드 Conversation 에서 두 화자가 서로 다른 음성(또는 최소 피치 차이)로 재생됨
2. **요구사항 13절 유지**: 전체/문장별 재생 시 이전 재생을 stop + QUEUE_FLUSH 로 끊어 겹치지 않음 (기존 테스트 7개 모두 통과)
3. **스토리 모드 중립**: Story 는 한 명의 narrator 만 있으므로 시각적·기능적 영향 없음
4. **증명**:
   - 단위 테스트: SpeakerVoices 배정 로직 (JVM)
   - 계측 테스트: ReaderSpeech 재생 계약 + 음성 변경 추적 (Android)
   - 에뮬레이터 검증: Medium_Phone_API_36.1 + Google TTS 에서 두 화자 구분되는 음성 또는 피치로 재생됨

## 구현 순서

1. **SpeakerVoices 로직 (JVM 테스트)**: 화자 이름/성별 → (음성, 피치) 배정 로직 (순수 함수)

## 2026-09-26 구현 기록
- `ui/reader/SpeakerVoices.kt`(순수 Kotlin): 화자 → (음성 이름, 피치) 배정. 화자 1명(스토리)은 기본 음성.
  네트워크 음성 제외, 품질·이름 순, 이름에서 성별이 읽히면(삼성 `SMTf/SMTm`, 구글 `#female/#male`) 여/남
  하나씩 앞에. 음성이 모자라면 같은 음성을 다른 피치로, 음성이 없으면 피치만 다르게. Google 의 일반 항목
  `en-US-language` 는 구체 음성 뒤로.
- `SpeechEngine` 에 `voices`/`setVoice`/`setPitch`, `ReaderSpeech.play(List<SpeechLine>)` 가 줄마다 음성·피치를
  `speak()` 직전에 설정. `SpeechLine(text, speaker)` 로 화면이 화자를 넘긴다. 표현 발음은 speaker 없음 → 기본 음성.
- 테스트: `SpeakerVoicesTest` 9건(JVM), `ReaderSpeechTest` 2건 추가(두 화자 다른 음성 + 발음은 기본 음성 복귀,
  음성 1개면 피치로 구분). 기존 재생 계약 테스트 8건 그대로 통과.

### 남은 것

### 2026-09-26 리뷰(code-critic) 반영
1. **[높음] 기본 음성 복귀가 기기 언어를 따라갔다.** `engine.defaultVoice` 는 기기 TTS 기본 언어(한국 폰이면 한국어)
   의 음성이고 `setVoice` 는 언어까지 덮어써서, 스토리 낭독·표현 발음·복습함 발음이 한국어 음성으로 영어를 읽는
   회귀가 있었다. 복귀를 `setLanguage(Locale.US)` 로 바꿨다(그 언어의 기본 음성이 선택됨).
2. **[높음] 문장별 재생에서 화자 음성이 사라졌다.** 한 줄만 재생하면 화자가 1명으로 보여 내레이터 취급.
   `ReaderSpeech.cast`(지문 전체 화자 명단)로 배정하도록 바꿨다. 전체 재생과 문장 재생에서 Anna 가 같은 목소리.
3. 화자가 바뀔 때만 `setVoice`/`setPitch` 호출(40줄 대화에서 80회 IPC 방지), 엔진이 음성을 거부하면 직전 화자
   음성이 남지 않도록 기본으로 폴백.
4. Google 로컬 음성 이름(`en-us-x-tpf-local` 등)에는 성별 토큰이 없어 추정이 안 된다. 근거 없는 매핑은 넣지
   않았다. 에뮬레이터에서는 "서로 다른 두 음성" 까지만 보장되고 남/여 대비는 삼성 SMT(`SMTf/SMTm`)에서 기대한다.
   **귀로 확인은 폰에서.**
5. 진단 로그는 DEBUG 빌드에서만.
6. `ReaderSpeechTest.kt` 가 280줄이 되어 분리: `RecordingSpeechEngine.kt`(공용 픽스처), `ReaderSpeechTest.kt`
   (계약 8건), `ReaderSpeechVoicesTest.kt`(음성 4건).

리뷰어가 확인해 준 것: AOSP `TextToSpeech` 는 `speak()` 시점의 voice/pitch 를 utterance 마다 스냅샷하므로
QUEUE_ADD 로 쌓인 각 줄이 자기 음성을 유지한다(삼성 엔진은 폰에서 확인할 항목). 재생 계약(stop + QUEUE_FLUSH,
지연 콜백 무시, 오류 처리)은 회귀 없음. 스토리에서 모델이 캐릭터 이름으로 화자를 나누면 스토리도 다중 음성이
되는데, 기능상 자연스러워 그대로 둔다.

### 2026-09-26 후속 리뷰 반영과 마감 상태
- `-language` 일반 항목은 후보에서 **제외**(뒤로 미루기만 하면 구체 음성 1개 기기에서 두 화자가 같은 소리·같은 피치가
  됐다). 구체 음성이 1개면 두 번째 화자는 같은 음성을 다른 피치로 받는다. 단위 테스트로 고정.
- 거부된 음성의 폴백은 화자별 `fallbackPitch`(1.0 / 0.8 / 1.2 / 0.9) 로 기본 음성을 쓴다. 두 화자가 모두
  폴백해도 구분된다. 기본 복귀 자체가 실패하면 같은 호출을 반복하지 않는다.
- 실제 엔진 계측 `AndroidSpeechEngineTest.goingBackToTheDefaultVoiceKeepsEnglishNotTheDevicesLanguage` 추가:
  이름 있는 음성 → `setVoice(null)` 뒤 현재 음성 로케일이 `en` 인지 확인. 에뮬레이터에서 스킵 없이 통과.
