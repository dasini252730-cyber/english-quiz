# 007 콘텐츠 읽기와 TTS

## 목적
대화와 이야기를 성인이 읽기 편한 형태로 제공하고 영어 발음을 들을 수 있게 한다.

## 작업 범위
- 대화 모드는 화자 구분, 스토리 모드는 읽기 편한 문단으로 표시한다.
- 전체 콘텐츠 순차 재생, 문장별 재생, 저장 표현 발음 재생을 제공한다.
- 전체 재생과 문장별 재생이 겹치지 않도록 재생 상태를 관리한다.
- 다음 단계 버튼으로 퀴즈에 진입한다.

## 완료 기준
- Conversation과 Story가 각각 적합한 레이아웃으로 보인다.
- 전체/개별 재생 전환에서 이전 음성이 중단되어 겹치지 않는다.
- 재생을 지원하지 못하는 문장에서도 화면이 안정적으로 동작한다.

## 실행 순서
1. 선행 task 004의 실제 Conversation/Story 목적지와 task 006의 구조화 응답 모델이 통합 가능한 상태인지 확인한다. 둘 중 하나가 대기 중이면 Reader는 구현 준비만 기록하고 완료 처리하지 않는다.
2. `AiLearningModels`의 segment/화자/표현 위치 계약을 Reader 표시 모델로 매핑한다. Conversation은 화자별 대화문, Story는 문단과 문장 경계를 유지해 문장별 재생이 가능하도록 한다.
3. Android 기본 `TextToSpeech`를 앱 범위에서 관리하는 재생 컨트롤러를 설계한다. 전체 재생, 문장 재생, 표현 재생 시작 전에 기존 utterance를 중단하고, 초기화 실패·지원하지 않는 언어·빈 문장은 화면을 중단시키지 않는 상태로 반환한다.
4. Reader Composable에서 전체 재생과 각 문장 재생 버튼을 연결하고 현재 재생 상태를 표시한다. 표현 터치는 004의 overlay 경로와 006의 의미 조회/자동 저장 경계를 사용하며, overlay를 닫아도 읽던 스크롤 위치를 보존한다.
5. 다음 단계 버튼은 생성/Reader 상태가 유효할 때만 퀴즈 목적지로 이동시키고, 오류나 TTS 미지원은 학습 콘텐츠 표시와 분리한다.
6. 모델 매핑, 재생 중단 경쟁, TTS 초기화/지원 실패, 전체→문장 전환, 다음 단계 callback을 Compose/JVM 테스트로 검증한 뒤 `lint`와 `assembleDebug`를 실행한다. 가능하면 Galaxy S24에서 전체/문장/표현 재생과 퀴즈 진입을 수동 확인한다.

### 재생 겹침 방지를 증명 가능하게 바꿈
`ReaderSpeech` 가 `TextToSpeech` 에 직접 묶여 있어, 실제 엔진으로는 "요청했다"만 알 수 있고 **두 음성이
겹쳤는지**는 관측할 수 없었다. 요구사항 13절의 핵심 기준이 증명 불가 상태였다.

- `SpeechEngine` 인터페이스로 Reader 가 실제로 쓰는 부분만 분리하고 `AndroidSpeechEngine` 이 실제
  `TextToSpeech` 를 감싼다. 프로덕션 동작은 그대로다.
- `ReaderSpeechTest` 8건을 계측 테스트로 추가했다(기록용 엔진 사용).
  - 새 요청은 큐에 넣기 **전에** `stop()` 을 부르고 첫 utterance 가 `QUEUE_FLUSH` 라 이전 재생이 밑에
    깔릴 수 없다 — 전체→문장, 문장→표현 전환이 모두 이 경로다.
  - 순차 재생은 자기 첫 utterance 뒤에만 `QUEUE_ADD` 로 쌓인다.
  - 교체된 이전 요청의 완료 callback 이 새 재생의 playing 상태를 끄지 못한다(generation 로 구분).
  - 영어 미지원, 엔진 거절, 빈/초과 길이 문장에서 화면이 계속 동작하고 오류만 표시된다.
  - `close()` 이후 요청은 무시되고 엔진은 shutdown 된다.

### 회전 시 유료 재생성·지문 손실 수정 (적대적 리뷰 지적)
`LearningSessionRoute` 의 `step` 이 `remember` 여서, 화면 회전·글자 크기 변경·프로세스 사망 후 세션이
`Preparing` 으로 되돌아가 **유료 생성 호출이 다시 나가고 읽던 지문이 다른 것으로 바뀌었다**. 같은 파일의
`retry`/`savedCountAtStart` 는 이미 `rememberSaveable` 이라 빠뜨린 것이 분명했다.

- `SessionStepSaver` 를 추가해 `step` 을 `rememberSaveable(stateSaver = ...)` 로 바꿨다. 콘텐츠는 Edge
  Function 이 주는 것과 **같은 JSON 형태**로 저장하고 복원 시 `parseContentResponse` 로 되읽는다. 복원
  경로가 실제 응답과 같은 검증을 통과하므로 별도 디코더가 따로 흘러갈 여지가 없다.
- `LaunchedEffect(retry)` 는 복원된 세션에서 즉시 반환한다. 재시도(`Failed`)와 최초 진입(`Preparing`)
  에서만 생성한다.
- `kotlin-parcelize` 를 먼저 시도했으나 AGP 9.4.0 의 내장 Kotlin 구성에서 컴파일러 플러그인이 붙지 않아
  `@Parcelize` 가 구현을 생성하지 못했다. 빌드를 흔드는 대신 이미 테스트된 JSON 경로를 재사용했다.
- `SessionStepSaverTest` 4건: Reading 이 표현 offset 까지 그대로 복원되는지, Quiz 가 지문과 진행 요약을
  함께 지니는지, 나머지 단계가 자기 자신으로 왕복하는지, 읽을 수 없는 저장값이 crash 대신 null 로
  떨어져 세션이 새로 시작되는지.
- `LearningSessionRouteTest.recreationMidSessionKeepsTheSessionInsteadOfPayingForANewPassage` 가
  회전 후 생성이 다시 호출되지 않음을 단언한다.
