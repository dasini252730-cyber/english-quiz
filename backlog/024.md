# 024 생성 출력 glossary 와 로컬 우선 뜻 조회

## 목적
사용자 결정(2026-09-26, 토큰 절감): 콘텐츠 생성 출력에 어휘표(glossary)를 포함하고, 단어/표현 터치 시 뜻을 로컬에서 먼저 찾는다(주석 표현의 meaning → glossary → 이미 저장된 표현의 뜻). AI 뜻 조회(meaning)는 셋 다 없을 때만 호출한다. Edge Function 스키마·검증·테스트와 앱 파서·Reader 조회 경로를 함께 바꾼다.

| `supabase/functions/ai-learning/index.test.mjs` | 테스트; glossary 필드 검증 및 생략 케이스 |

| `app/src/main/kotlin/com/englishquiz/app/data/repository/LearningRepository.kt` | 저장된 표현의 contextMeaning 을 lookupMeaning 에 전달할 메서드 추가 (옵션: getSavedExpressionMeaning) |

## 작업 범위

**1단계: Edge Function 스키마·검증·시스템 프롬프트**
- CONTENT_SCHEMA 에 `glossary` 배열 필드 추가: `{ term: string, meaning: string }[]`
- validateModelOutput 에서 glossary 필드 검증 (8~100 항목, 각 term/meaning 은 1~80자)
- 시스템 프롬프트에 "glossary 를 포함하고, 어휘표에서 중복 없이 새 표현만 모은다" 지시 추가
- index.test.mjs 에 glossary 검증 3건 추가: 정상 케이스, glossary 생략, 중복 항목

**2단계: 앱 모델·파서 갱신**
- ContentExpression: meaning 필드 유지 (주석 표현용, 선택)
- LearningContent: glossary: Map<String, String> 또는 List<Pair<String, String>> 추가
- parseContentResponse: glossary 배열 → Map<String, String> 파싱
- toResponseJson: LearningContent.glossary → glossary 배열 직렬화

**3단계: Reader 뜻 조회 로직 (ReaderMeaningLookup.kt)**
- lookupMeaning 함수 내에서 순차 확인:
  1. token.lookup 이 ContentExpression 목록에 있으면 → expression.meaning 반환 (API 호출 0)
  2. token.lookup 이 LearningContent.glossary 에 있으면 → glossary[term] 반환 (API 호출 0)
  3. repository.findSavedExpression(token.lookup) → contextMeaning 반환 (API 호출 0)
  4. 모두 없으면 → explainMeaning 호출 (API 호출 1)
- MeaningRequest 와 ContextualMeaning 타입은 유지

**4단계: 테스트**
- 단위 테스트: lookupMeaning 함수
  - 주석 표현 문제 없음 (정시간 내 API 호출 0)
  - glossary 에 있는 단어 (API 호출 0)
  - 저장된 표현 (API 호출 0)
  - 셋 다 없는 단어 (API 호출 1)
- Edge Function 테스트: index.test.mjs (이미 위 1단계에서 정의)
- 계측 테스트: ReaderScreen (기존 것과 통합)

## 완료 기준

- **주석 표현 뜻 조회**: ContentExpression.meaning 이 있으면 API 호출 0 (ReaderMeaningLookup 단위 테스트 증명)
- **Glossary 조회**: 콘텐츠의 glossary 항목을 탭하면 API 호출 0 (단위 테스트)
- **저장 표현 뜻 조회**: 기존 저장 표현을 다시 탭하면 repository 캐시만 조회, API 호출 0 (단위 테스트)
- **새 단어만 API**: 주석·glossary·저장 캐시 모두 없는 단어를 탭할 때만 explainMeaning 호출 (테스트)
- **Edge Function 검증**: glossary 필드 구조 및 중복 제거 (index.test.mjs 통과)
- **JSON 왕복**: toResponseJson → parseContentResponse 후 ContentExpression, glossary 모두 복원 (파서 테스트)
- **앱 빌드**: lint, testDebugUnitTest, assembleDebug, connectedDebugAndroidTest 통과
- **에뮬레이터 검증**: Reader 화면에서 세 가지 원천의 뜻을 올바르게 표시
