## 구현 메모 (2026-10-10)
- 서버: `usage.ts`(토큰 비교, Seoul 날짜, PostgREST로 `ai_usage` 카운트·기록), `index.ts`(헤더 `x-app-token` 검사 → 401 `unauthorized`; 토큰 미설정이면 503 `service_not_configured`로 닫힘; 하루 상한 `AI_DAILY_LIMIT`(기본 40) 초과 시 429 `daily_limit_reached`; 시도마다 기록). 상한은 공급자 시도 수 기준이라 재시도 1회는 2회로 센다. 기록·카운트 실패는 로그만 남기고 호출은 통과(계정 처리가 지문 생성을 막지 않도록).
- DB: `supabase/migrations/20261010150000_ai_usage.sql` — 테이블, day 인덱스, RLS(정책 없음), `ai_usage_monthly` 뷰(security_invoker).
- 앱: `-PaiAppToken` → `BuildConfig.AI_APP_TOKEN` → `X-App-Token` 헤더. 401/429 문구 분리. CI는 `AI_APP_TOKEN` 시크릿.
- 배포 순서(README): GitHub 시크릿 → APK 빌드·설치 → `supabase db push` → `supabase secrets set AI_APP_TOKEN` → `supabase functions deploy`. 순서를 바꾸면 기존 APK가 401을 받는다.
- 2026-10-10 원격 DB에 `db query --linked -f`로 적용하고 `migration repair --status applied`로 기록을 맞췄다(RLS on, 정책 0, 뷰 1). 함수 배포와 `AI_APP_TOKEN` 시크릿 설정은 사용자가 GitHub 시크릿을 넣고 새 APK를 설치한 뒤에 한다(README 순서).
