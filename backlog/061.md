# 061 학습 기록 일관성 시나리오 계측 테스트 (세션 중복·스트릭·복습 일정·답변 기록·점수 합)

## 목적
2026-10-10 사용자 요청. 시나리오 하나를 순서대로 돌린다: 오늘 지문 읽기 → 일일 퀴즈 완료 → 결과 화면에서 프로세스 종료 후 재시작 → 같은 날 다른 모드 완료 → 다음 날로 시계 이동 → 복습 퀴즈에서 한 표현을 오답→정답→오답→정답. 단계마다 learning_sessions가 모드별 한 건(재시작 후 중복 없음), 스트릭은 하루에 1만 오름, saved_expressions의 연속 정답 1·다음 복습 오늘+1일, quiz_answers에 되묻기 미기록·일정 변경과 기록이 한 트랜잭션, 누적 점수·레벨이 세션 점수 합과 일치함을 검증. 시계는 주입하고 시스템 시간에 의존하지 않는다. 함께 ResultScreenTest 간헐 크래시(018)를 재현·원인 조사.

## 작업 범위

### 1단계: LearningHome에 시계 주입 인터페이스 추가
- LearningHome 시그니처 변경: `nowEpochMillis: () -> Long = System::currentTimeMillis`, `zoneId: ZoneId = ZoneId.systemDefault()` 추가
- LearningHome이 호출하는 LearningSessionRoute, HomeSummaryRoute에 이들 파라미터 전달

### 2단계: HomeSummaryRoute 수정
- `todayIso()` 함수를 파라미터화된 `todayIso: () -> String` 람다로 변경하거나, `nowEpochMillis`, `zoneId`를 받아서 내부에서 계산
- System.currentTimeMillis() 직접 호출 (줄 73)를 ReviewQueue.of(expressions, nowEpochMillis()) 로 변경
- LearningHome에서 주입받은 시계로 todayIso 계산 후 전달

### 3단계: LibraryRoute 수정
- `today: LocalDate = LocalDate.now()` 파라미터를 `today: LocalDate = LocalDate.now(Clock.systemDefaultZone())`로 또는 호출자가 주입하도록 변경
- 필요 시 LearningHome에서 계산하여 전달

### 4단계: HomeSummary 및 ReviewQueue 호출 체인 확인
- HomeSummaryRoute에서 GameStatsPolicy.compute() 호출 시 이미 todayIso String 전달됨 (줄 67) ✓
- ReviewQueue.of() 호출이 nowEpochMillis를 받도록 확인 (줄 73)

### 5단계: ContentPrefetcher (선택적)
- 생성자에서 주입 받은 zoneId와 nowEpochMillis를 이미 보유함. 테스트 생성 시 넘길 때 override 가능.
