# 014 전체 학습 흐름 통합

## 목적
요구사항의 대표 사용자 여정이 앱 안에서 끊김 없이 완주되도록 모든 기능을 연결한다.

## 작업 범위
- 최초 실행 → 진단 → 홈 → 대화/스토리 생성 → 읽기/TTS → 표현 뜻/자동 저장을 연결한다.
- 다음 단계 퀴즈 → 복습 상태 갱신 → 결과/스트릭 표시를 연결한다.
- 앱 종료/재실행 후 기존 데이터가 유지되는지 확인한다.
- 다음 학습 콘텐츠와 퀴즈에서 저장 표현이 다시 활용되는지 확인한다.

## 완료 기준
- 요구사항 25장의 18개 흐름을 end-to-end로 수행할 수 있다.
- 주요 로딩/오류/빈 상태가 각 흐름에 반영된다.
- 발견한 결함은 수정되거나 별도 backlog 항목으로 기록된다.

### 발견한 결함 — 저장한 표현이 퀴즈에 영영 나오지 않음 (수정함)
1회차에서 표현을 1개 저장했는데 바로 이어진 퀴즈가 "오늘 복습할 표현이 없어요" 를 띄웠고, 재실행 후
2회차에서도 같았다. 데이터는 정상이었다(홈 지표 1개, 복습함 1개, 재실행 후에도 유지).

원인은 출제 대상이 아니라 **오답 보기**였다. `QuizBuilder.buildOptions` 가 오답을 다른 저장 표현의
뜻에서만 만드는데, 저장 표현이 1개면 오답 후보가 0개라 `MIN_OPTIONS = 2` 를 못 채우고 `buildQuestion`
이 `null` 을 돌려준다. `mapNotNull` 이 그 문항을 조용히 버리고, 결과적으로 빈 퀴즈가 되어 사용자에게는
"복습할 표현이 없다"고 표시된다. **첫 세션은 정의상 저장 표현이 적으므로 모든 신규 사용자가 겪는다.**

수정: 오답 후보를 오늘 콘텐츠의 나머지 표현에서도 가져온다. 생성 응답이 표현마다 뜻을 이미 포함하므로
AI 추가 호출이 없다(요구사항 22 유지). 같은 표현이 양쪽에 있으면 사용자가 저장한 뜻이 우선한다.
`QuizBuilderTest` 에 3건을 추가해 고정했다.
- `theFirstSessionsSingleSavedExpressionStillGetsAQuestion` — 이 결함 자체.
- `aLoneExpressionWithNothingElseToOfferStillProducesNoQuestion` — 그래도 보기를 못 채우면 빈 퀴즈가
  맞다. 보기 1개짜리 가짜 문제를 만들지 않는다.
- `aSavedExpressionsOwnMeaningWinsOverThePassagesWording` — 중복 시 저장된 뜻 우선.

### 함께 고친 것
- `AssessmentFlowTest.failedSaveKeepsAssessmentOpenAndRetryMovesHome` 가 재시도 클릭 직후 DataStore
  저장을 기다리지 않고 홈을 단언해 간헐 실패했다. 이 세션 첫 실행에서 실제로 터졌고 이후 실행에서는
  통과해 플레이크로 남아 있었다. 같은 파일의 다른 테스트처럼 `waitUntil` 로 기다린다.

### 완료 기준 대조
- **요구사항 25장의 흐름을 end-to-end 로 수행할 수 있다** — 위 경로를 실제 앱에서 완주했다.
- **주요 로딩/오류/빈 상태가 각 흐름에 반영된다** — 생성 대기 화면, 생성 실패 3종 안내와 재시도
  (`LearningSessionRouteTest`), 뜻 조회 실패/저장 실패 재시도(`ReaderScreenTest`), 빈 퀴즈 안내,
  빈 복습함 안내, 스트릭 조회 실패 재시도가 모두 덮여 있다.
- **발견한 결함은 수정되거나 별도 backlog 항목으로 기록된다** — 위 두 건 모두 수정했다.

### 간격 반복에 대한 관찰 (결함 아님)
1회차 직후 2회차 퀴즈가 비는 것은 **정상 동작이다.** 방금 답한 표현은 `recordAnswer` 가 다음 복습
시각을 미래로 밀어 두므로 기한이 아니고, 몇 분 만에 같은 표현을 다시 묻는 것은 간격 반복을 무력화한다.
처음엔 결함으로 의심했으나 코드와 요구사항 14.1 을 대조해 앱이 옳다고 판단했다. 대신 2회차가 자기
표현을 새로 저장하고 그것이 출제되는지를 확인하도록 주행 쪽을 고쳤다. 기한이 도래한 과거 표현이 다시
출제되는 경로는 시계를 통제할 수 있는 `QuizBuilderTest.dueExpressionNotInTodayContentIsStillIncluded`
와 `ReviewProgressPersistenceTest` 가 덮는다.

### 최종 주행 결과 (2026-09-24)
```
1회차: 진단 8문항 -> 홈(0일/0개/0개) -> Conversation 생성 -> Reader
       -> 표현 뜻+자동 저장 2건 -> 퀴즈 2문항 -> 결과(정답률 50%, 1일 연속) -> 홈(1일/2개/0개)
재실행: 강제 종료 후 홈 지표 유지(1일/2개/0개), 복습함 2개
2회차: Story 생성 -> Reader -> 표현 저장 1건 -> 퀴즈 1문항 -> 결과 -> 홈
```
중간에 에뮬레이터가 한 번 네트워크를 잃었을 때 앱이 "네트워크 연결을 확인해 주세요." 와 재시도 버튼을
표시했다. 의도한 오류 경로가 실제 조건에서 동작하는 것을 우연히 확인한 셈이다.

주행 스크립트는 세션 산출물이라 저장소에 넣지 않았다. 재현하려면 `-PaiEndpoint=<함수 URL>` 로 빌드해
설치한 뒤 진단 -> Conversation -> 표현 터치 -> 퀴즈 -> 결과 -> 강제 종료 -> 재실행 -> 복습함 -> 2회차
순으로 따라가면 된다.
