# 042 지문 이해도 질문 2~3개 (생성 응답에 포함)

## 목적
2026-10-02 사용자 결정. Edge Function이 지문과 함께 comprehension 질문 2~3개(한국어 질문, 선택지 4개, 정답, 해설)를 같은 응답으로 돌려주고, 앱은 퀴즈 앞부분에 이 질문을 넣어 '흐름을 이해했는지'를 묻는다. 호출 횟수 변화 없음, 출력 토큰 약 10% 증가(사용자 수락).

## 작업 범위

1. **Edge Function (supabase/functions/ai-learning/index.ts)**
   - CONTENT_SCHEMA에 optional `comprehension` 배열 추가: 각 항목은 question(문자열), options(4개 문자열 배열), answerIndex(정수), explanation(문자열) 포함
   - passageContract()에서 2~3개의 지문 이해도 질문 요청
   - validateModelOutput()에서 comprehension 항목 검증 (나쁜 항목 드롭, 지문 전체 실패 안 함)

2. **Edge Function 테스트 (supabase/functions/ai-learning/index.test.mjs)**
   - comprehension 질문 포함된 응답에 대한 테스트 케이스 추가

3. **데이터 모델 (app/src/main/kotlin/com/englishquiz/app/domain/quiz/QuizModels.kt)**
   - QuizQuestionType enum에 COMPREHENSION 추가
   - ComprehensionQuestion 데이터 클래스 정의: question, options, answerIndex, explanation

4. **AI 응답 파싱 (app/src/main/kotlin/com/englishquiz/app/data/ai/AiLearningResponses.kt)**
   - LearningContent에 optional `comprehension: List<ComprehensionQuestion>` 필드 추가
   - Edge Function 응답에서 comprehension 배열 파싱
   - toResponseJson()에서 comprehension을 JSON으로 직렬화

5. **퀴즈 생성 (app/src/main/kotlin/com/englishquiz/app/domain/quiz/QuizBuilder.kt)**
   - comprehension 질문을 먼저 배치
   - 각 comprehension 항목을 QuizQuestion 변환 (type=COMPREHENSION, expression 필드 없음)

6. **퀴즈 화면 (app/src/main/kotlin/com/englishquiz/app/ui/quiz/QuizRoute.kt)**
   - COMPREHENSION 타입 질문에서 recordAnswer() 스킵

7. **테스트**
   - AiLearningResponsesTest.kt: comprehension 파싱 및 직렬화 테스트
   - QuizBuilderTest.kt: comprehension 질문이 먼저 나오는지 확인
   - QuizRouteTest.kt: COMPREHENSION 타입 처리 테스트
   - SessionStepSaverTest.kt, ContentPrefetcherTest.kt: 필요시 업데이트

## 완료 기준

- Edge Function이 2~3개의 comprehension 질문을 JSON 응답에 포함
- 나쁜 comprehension 항목은 드롭되고 지문 전체는 실패하지 않음
- 앱이 comprehension 배열을 파싱하고 저장
- QuizBuilder가 comprehension 질문을 퀴즈 앞에 배치
- COMPREHENSION 타입 질문은 표현 녹음(recordAnswer) 없음
- QuizScreen이 comprehension 질문을 올바르게 표시하고 사용자 응답 처리
- 저장된 지문에서 comprehension 없는 이전 데이터도 계속 로드됨
- Edge Function 테스트와 앱 AndroidTest 모두 통과

## 구현 메모 (2026-10-02)
- 서버: `CONTENT_SCHEMA.comprehension`(question, options[], answerIndex, explanation; required에 포함 — Anthropic 구조화 출력은 길이 제약을 못 쓰므로 개수는 프롬프트+검증으로). `validateComprehension`: 질문 300자·선택지 2~5개(중복 불가)·answerIndex 범위 검사, 나쁜 항목은 버리고 최대 3개, 없어도 지문은 통과(용어집과 같은 "덤" 규칙). 프롬프트는 "지문의 상황·어조 이해를 묻고 표현 뜻은 묻지 말 것, 한국어 질문, 선택지 4개, 다음 대답 고르기는 영어 선택지".
- 앱: `LearningContent.comprehension`(기본 빈 목록 → 042 이전 저장 지문도 읽힘), 파서는 느슨하게(불량 항목 건너뜀), `toResponseJson` 왕복.
- `QuizQuestionType.COMPREHENSION`: `expression=""`, 퀴즈 맨 앞, 표현 상한(10/15) 밖. `QuizRoute.record`는 이 유형을 건너뛰고(기록할 표현 없음), 재생성 시 다시 만들어지는 문제라 `comprehensionDone`(rememberSaveable)만큼 앞에서 잘라 이어 풀기.
- 라이브러리 다시 읽기에도 같은 질문이 나온다(비용 0, 의도).
- 테스트: 함수 `index.test.mjs` 20/20, `AiLearningResponsesTest`(왕복·불량 건너뜀·옛 지문), `QuizBuilderTest.thePassagesOwnQuestionsComeFirst…`, `QuizScreenTest.aComprehensionQuestion…`, `QuizRouteTest.aPassageQuestionOpensTheQuizAndRecordsNothing`.
- 배포: `supabase functions deploy ai-learning` 필요(세션 요약에 상태 기록).
- 리뷰(code-critic) 반영: ① 지문 질문은 답한 순간 `comprehensionDone`을 올려 회전/프로세스 사망 후 같은 질문이 다시 나오지 않음(점수 이중 가산 차단, `QuizRouteTest`가 StateRestorationTester로 증명). ② 선택지 하나가 비면 인덱스가 밀리므로 항목을 통째로 버림(서버·앱 양쪽, 테스트 추가). ③ 같은 지문에 다시 들어가면(그 모드 세션이 오늘 이미 기록됨) 지문 질문을 건너뛰어 반복 득점 불가; 라이브러리 다시 읽기도 건너뜀(`QuizRoute.skipComprehension`).
