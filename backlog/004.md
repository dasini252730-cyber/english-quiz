# 004 홈과 앱 내비게이션

## 목적
앱 실행 후 별도 로그인 없이 진단 또는 학습 시작 화면으로 안내한다.

## 작업 범위
- 진단 미완료 시 진단, 완료 시 홈으로 분기한다.
- 홈에 스트릭, 저장 표현 수, 암기 완료 수를 표시한다.
- Conversation, Story, 복습함 진입 동선을 제공한다.
- 콘텐츠 학습 → 퀴즈 → 결과 → 홈 기본 경로를 구성한다.
- 표현 의미는 별도 화면 대신 현재 Reader 위 overlay로 표시한다.

## 완료 기준
- 요구사항의 화면 전환 흐름대로 이동할 수 있다.
- Overlay를 닫으면 이전 Reader 위치를 유지한다.
- 로그인 화면 및 MVP 제외 화면은 노출하지 않는다.

- `app/src/main/kotlin/com/englishquiz/app/ui/EnglishQuizApp.kt` — 현재 DataStore 진단 상태에 따라 진단 화면 또는 홈 placeholder를 표시한다. 독립형 `HomeScreen`과 앱 내 화면 호스트를 연결할 위치.

- 003에서 구현할 진단 화면/완료 상태 흐름 — 선행 완료 후 시작 분기를 연결하고, 진단 저장 성공 시 홈으로 이동하는 동작을 재사용한다.

- 필요한 테스트 파일 — 진단/홈 시작 분기, Reader 의미 Overlay 표시 후 닫을 때 상태 보존, 실제 제공되는 목적지 이동과 뒤로가기 동작을 검증한다.

## 실행 순서
1. 선행 작업 003의 진단 화면, DataStore 연동, 결과 저장 성공 후 홈 이동이 완료되었는지 확인한다. 앱 설정 Flow에 이미 있는 `isAssessmentComplete`를 단일 시작 분기 기준으로 사용한다.
2. 현재 구현된 데이터 API로 홈의 저장 표현 수 및 암기 완료 수를 관찰할 수 있는지 확인하고, 없는 스트릭/집계 기능은 현 백로그 범위 안에서 임의로 계산하지 말고 관련 작업 의존성을 확인한다.
3. 화면 목적지와 상태 소유권을 설계한다. Reader의 스크롤/현재 위치 상태가 의미 Overlay 표시와 닫힘 사이에 유지되고, 뒤로가기가 일관되게 동작하게 한다.
4. 홈의 Conversation, Story, 복습함 동선을 연결한다. 후속 기능이 아직 준비되지 않은 경로가 있으면 범위와 연결 상태를 구분하여 허위 완료 UI를 만들지 않는다.
5. 기존 요구사항의 콘텐츠 → 퀴즈 → 결과 → 홈 흐름을 구현 가능한 선행 task와 매핑한다. 현재 미구현인 목적지가 있으면 적절한 후속 backlog 항목을 확인하고 해당 acceptance criteria를 검증 가능하게 정리한다.
6. 진입 분기, 목적지 이동, 뒤로가기 및 Overlay 위치 보존의 테스트를 실행한 뒤 Android lint와 `assembleDebug`를 실행한다.
