# 029 Anthropic API 키 거부 (provider_auth) — 사용자 확인 필요

## 증상 (2026-09-27 10:3x~)
Edge Function 의 모든 호출이 `{"error":{"code":"provider_auth"}}` (HTTP 502) 로 끝난다. `content`·`meaning` 모두.
`provider_auth` 는 Anthropic 이 401/403 을 돌려줄 때만 나오는 코드다.

## 코드 문제가 아닌 근거
- 028(프롬프트) 변경 전후 동일하게 실패하며, 프롬프트와 무관한 `meaning` 도 실패한다.
- 코드가 만들 수 있는 오류는 400(`provider_request_rejected`)이지 401/403 이 아니다.
- `ANTHROPIC_API_KEY` 시크릿은 9/21 이후 변경되지 않았고 목록에 존재한다.
- Anthropic 상태 페이지: 전 서비스 Operational (최근 장애는 9/22 해결).
- 어제(9/26) 하루 종일 수십 회 정상 호출.

## 사용자가 확인할 것 (Anthropic Console)
1. API 키가 삭제/재발급/비활성화되지 않았는지.
2. 조직/계정 상태(제한, 결제 문제) 및 월 지출 한도.
3. 새 키를 발급했다면 **사용자가 직접**:
   `supabase secrets set ANTHROPIC_API_KEY=<새 키> --project-ref uqtkmwqqigbtzcoumrly`
   (재배포 불필요, 수십 초 뒤 반영.)

## 완료 기준
`meaning` 호출 1회, `story` 생성 1회가 200 으로 돌아오면 닫는다. 그 뒤 028 검증을 이어간다.

## 2026-09-28 해결
사용자가 새 Anthropic API 키를 발급했고, 이 세션에서 `supabase secrets set ANTHROPIC_API_KEY=… --project-ref …` 로
넣었다(재배포 없음). `meaning` 200, `story` 생성 200 확인. 원인은 기존 키의 폐기/무효화로 추정(Anthropic 쪽).
주의: 키가 대화 기록에 남았으므로 나중에 한 번 더 재발급하는 편이 안전하다. `done`.
