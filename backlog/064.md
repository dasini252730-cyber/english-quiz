## 작업 범위

### 0. 결정 사항 (2026-10-13, 메인 에이전트)
- 규칙 본문은 `supabase/functions/ai-learning/story-rules.ts`의 `STORY_RULES`에 그대로 두고, 스토리 회차 프롬프트와 시즌 설계 프롬프트 양쪽에 통째로 보낸다(섹션 8은 회차에도 맥락이 된다). 대화 프롬프트는 READER/PRINCIPLE/WORLD를 계속 쓴다.
- SEASON_TOPIC은 기존 전제 목록(`SEASON_TOPICS`, 옛 STORY_PREMISES)에서 시즌 설계 시 하나 뽑는다. 시즌 밖 단독 스토리(시즌 컨텍스트가 깨졌을 때의 대체 경로)는 "a season of one"으로 자기 주제를 하나 받는다.
- JSON 스키마는 바꾸지 않는다. 섹션 8의 플랜 요소는 기존 필드에 매핑한다: `conflict` = 중심 상황·흥미 이유·WHAT IS TRUE·결말, `characters[].role` = 역할 + 지나치게 진지한 규칙, `motive` = 지금 원하는 것, `secret` = 들키고 싶지 않은 것 + 지키는 자아상, `episodes[].plan` = 무엇이 바뀌고 어떤 사실이 공개되며 독자가 그 뒤 무엇을 믿는지, `openQuestions` = 1화 뒤 독자의 질문. 서버가 받는 `conflict`/`characters` 상한은 1,200자(`MAX_SEASON_LINE`).
- 회차 브리프는 `episodeShape()`로 섹션 8의 위치(1화/2~3화/4~5화/6화/7화)를 한 줄 덧붙이고, 마지막 화가 아니면 "무언가는 해결하되 중심 질문은 열어 둔다"로 바꾼다(기존 "do not resolve the central conflict yet" 대체).
- 앱은 `SeasonBible.castLine(maxChars)`으로 인물의 역할·욕구·비밀·관계를 회차 요청에 보낸다(APK 재배포 뒤 적용). 인물마다 같은 몫을 주어 긴 캐스트에서도 뒷사람이 통째로 사라지지 않는다. 앱·서버 상한 2,400자(`MAX_CAST_LINE`). `peopleLine()`은 대화용으로 그대로.
- 리뷰 반영(code-critic): 시즌 설계도 검증의 `conflict`/`plan`도 1,200자로 올려 저장 전에 잘리지 않게 했다. 규칙 9절("맞지 않으면 건너뛴다")과 검증기(복습 표현 전부 누락 시 거부)의 모순은 규칙 본문을 건드리지 않고 회차 브리프에 "최소 하나는 글자 그대로 들어가야 한다"를 한 줄로 밝혀 해소했다(`reviewFloorClause`). 시즌 회차 브리프에는 SEASON_TOPIC이 이미 플랜에 녹아 있다는 한 줄을 넣었다.

### 1. Edge Function 프롬프트 변경
- `READER`, `PRINCIPLE`, `WORLD` 상수를 새 "Story Generation Rules (v2)" 내용으로 교체
  - 현재: 개별 상수로 분리된 취향 지침
  - 변경: 통합 규칙 블록으로 통합 (사용자 2026-10-13 지침 참조)
- `prompts()` 함수의 story/season 분기에서 새 규칙 적용
- 기존 스키마, 레벨 루브릭, 검증 로직은 유지
- 대화(conversation) 프롬프트는 변경 없음

### 2. SEASON_TOPIC 추가
- 기존 `STORY_PREMISES` 목록에서 랜덤 선택하여 프롬프트에 전달
- `storyPremise()` 함수의 역할 확인 및 필요시 명칭/구조 조정

### 3. peopleLine() 확대
- `SeasonBible.peopleLine()` 메서드를 수정하여 각 인물의 정보 포함:
  - 기존: `"Name (role)"`
  - 변경: `"Name (role; motive: X; secret: Y; relationships: Z)"` 형식 (또는 프롬프트에 맞는 자연스러운 형식)
- 모든 문자 데이터 (motive, secret, relationships)는 이미 SeasonCharacter에 있음
- 스토리 요청(SeasonCoordinator 라인 85)만 바꾸고 대화용 peopleLine()(라인 137)은 그대로

### 4. 테스트 업데이트
- 프롬프트 테스트: 새 규칙이 시스템 프롬프트에 포함되는지 확인
- SeasonCoordinator 테스트: 확대된 peopleLine() 형식이 정확히 전달되는지 검증 (라인 141, 156)
