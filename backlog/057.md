## 목적
2026-10-10 사용자 지침. 꽃 단계인데 빈칸 문장을 못 만드는 표현은 뜻 고르기로 대체하지 말고 한국어 뜻을 보여주고 영어 표현을 직접 입력하게 한다(회상 없이 열매에 오르는 일 방지). 예문은 지문 문장을 그대로 보관한다(현행). 보기를 2개도 못 만들거나 정답 판별이 어려운 표현은 숙달로 승급시키지 않고 '출제 불가' 상태로 복습함에서 구분해 보여준다.

## 기술 결정 사항

### TYPED_MEANING UI 구현 방식
- QuizTypedAnswer 내에서 type 확인하여 표시 로직 분기
  * TYPED_BLANK: "영어 표현 입력", questionText = 영어 빈칭 문장
  * TYPED_MEANING: "영어 표현 입력", questionText = 한국어 뜻

### mastery 정책
- ReviewPolicy.recordAnswer()에서 조건 분기:
  * if (wasCorrect && nextStreak >= 4 && !expression.isNotAskable) { isMastered = true }

### isNotAskable 판정 시점
1. **Quiz 생성 시**: QuizBuilder.askability()로 표현 판정, 생성 불가 시 생략
2. **이후 상태 추적**: 표현을 생략한 경우 isNotAskable=true로 마킹 필요
   - 현재는 buildQuestion()이 null 반환하면 선택되지 않음
   - 향후 추적하려면: 별도 체크 단계나 학습 후 판정 필요

## 구현 메모 (2026-10-10)
- `QuizQuestionType.TYPED_MEANING`: 꽃 이상인데 빈칸 문장이 없으면 짧은 뜻(없으면 전체 뜻)을 보여주고 표현을 입력. 입력 UI와 채점은 `TYPED_BLANK`와 같다.
- `QuizBuilder.isAskable(expression, pool)`: 같은 빌더로 문제를 만들어 보고 null이면 출제 불가. 별도 컬럼 없이 복습함이 그때그때 계산한다(`ReviewUiState.Ready.unaskable`). 칩 "출제 불가"(열매는 제외).
- 숙달 보류는 따로 두지 않는다: 출제 불가 표현은 문제로 나오지 않으므로 연속 정답이 쌓일 수 없다.
- 리뷰 반영: 뜻 문장이 표현을 인용하면(`"call it a day"는 …`) 표현을 ____로 가린 뒤 보여 준다. 가리고 나서 남는 게 없으면 출제 불가. 출제 불가 판정은 복습함만 기준으로 하며(오늘 지문의 표현이 빈칸 보기를 보태 줄 수는 있음), 새 표현은 카드가 가능하므로 항상 출제 가능. 계산은 `Dispatchers.Default`에서 한다.
