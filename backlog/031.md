# 031 오늘 지문의 노란 표현을 탭 없이 전부 퀴즈에

## 배경
사용자 피드백(2026-09-28): 퀴즈가 너무 적다. 원인: 퀴즈 대상이 "탭해서 저장한 표현 + 기한 도래 표현" 뿐이라 첫날
2개 탭하면 2문항. 노란 표현이라도 안 탭하면 퀴즈에 안 나왔다. 제안 A/B/C/D 중 **A 만 선택**.

## 변경
- `ui/quiz/ContentEnrolment.kt` `enrolContentExpressions(content, repository, savedAt)`: 지문의 주석 표현을
  **탭한 것과 똑같이** 저장한다 - 리더의 `tokenize` 가 잘라내는 토큰 텍스트(가장자리 문장부호 제거)와
  `localMeaningFor` 의 뜻, 문맥 문장은 해당 세그먼트. 모델 주석 텍스트를 그대로 쓰면 "get a grip." 과 "get a grip" 이
  두 행이 되는(요구사항 22 위반) 문제를 리더와 같은 경로로 막는다. 이미 있으면 그대로(IGNORE). 새로 넣은 개수를 돌려준다.
- `LearningRepository.saveExpressionIfNew(...)`: `saveExpression` 과 같은 INSERT IGNORE, 실제로 넣었는지 Boolean.
- `QuizRoute(enrolExpressions = true, onExpressionsEnrolled = {})`: 로딩 직전에 등록(실패해도 퀴즈는 탭한 표현으로
  진행), 그 뒤 due 를 읽는다. 새 행은 `nextReview = null` 이라 due 이고, 답하면 +1일로 밀려 같은 날 재진입에서는
  재출제되지 않는다(`ReviewPolicy` 최소 간격 1일, 오답도 동일).
- `LearningSessionRoute`: `enrolExpressions = initialContent == null` - **라이브러리 재독은 등록하지 않는다**(026 계약:
  아무것도 저장하지 않음). `onExpressionsEnrolled = { savedCountAtStart += it }` - 자동 등록분은 "새로 저장한 표현"에서
  제외한다. 그 수가 난이도 정책(013, 평균 저장 ≤2 이면 상향)의 입력이라, 매일 5개가 자동으로 들어가면 난이도가 영원히
  오르지 못하는 회귀를 막기 위함. 결과 화면 "학습한 표현"(=퀴즈 문항 수)에는 포함된다.
- 문항 상한 10(`QuizBuilder.MAX_QUESTIONS`) 유지. 요구사항에 문항 수 규정은 없다. 기한 지난 표현이 먼저, 오늘 새 표현이
  뒤에 오므로 밀린 복습이 많은 날은 오늘 표현 일부가 다음 날로 넘어간다 - 정렬상 영구 기아는 없음.

## 테스트 (에뮬레이터)
- `QuizRouteTest.todaysAnnotatedExpressionsAreQuizzedWithoutBeingTappedAndEnterTheReviewBox`: 탭해 둔 "hang out"
  은 원래 뜻 유지, 주석 "sketchy."는 "sketchy" 키로 등록, 새로 등록 1개 보고, "1 / 2", 두 문항 답 후 둘 다 복습
  일정 잡힘.
- `LearningSessionContentTest.todaysPassageEnrolsItsExpressionsForTheQuizWithoutCountingThemAsNewlySaved`: 탭 없이
  "1 / 1" 퀴즈, 기록된 세션의 newlySaved = 0, quizQuestionCount = 1.
- `LearningSessionContentTest.aLibraryPassageIsReadAsItIsWithoutGeneratingOrStoring`: 라이브러리 재독 후 퀴즈에
  들어가도 저장 표현 0.
