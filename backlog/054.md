# 054 Story와 Conversation 연결 + 다음 편이 궁금한 연속성

## 목적
2026-10-08 사용자 지침. 지문마다 영어 줄거리(synopsis)를 받아 저장하고, 대화 생성 시 같은 날 스토리의 줄거리·인물·장소를 넘겨 그 상황을 연습하게 하며, 스토리 생성 시 직전 스토리 줄거리를 넘겨 이어지거나 참조하게 한다(인물 반복 가능). 선생성도 같은 순서(스토리→대화).

## 작업 범위
- 서버: 응답 스키마에 `synopsis` 필수, 요청에 `previousStory`/`companion` 수용, `connectionClause`로 프롬프트에 전달.
- 앱: `LearningContent.synopsis` 저장·왕복, `LearningDao.findLatestDailyContentBefore`, `LearningRepository.findPreviousSummary`, 세션 생성·선생성에서 요약 전달, 선생성 순서 스토리→대화.

## 완료 기준
- 생성 응답의 `synopsis`가 Room에 저장되고 다시 읽힌다(옛 행은 "").
- 스토리 생성 요청에 직전 스토리 요약이, 대화 생성 요청에 같은 날 스토리 요약이 실린다.
- 잘못되었거나 한국어인 요약은 버리고 생성은 계속된다(400 아님).
- 선생성은 스토리를 먼저 만들고 그 요약을 대화에 넘긴다.
- 앱 계측 테스트(`AiLearningResponsesTest`, `LearningRepositoryTest`, `ContentPrefetcherTest`)와 서버 테스트 통과.

## 구현 메모 (2026-10-08)
- 서버: 응답에 `synopsis`(영어 두 문장, 600자 상한, 없으면 ""), 요청에 `previousStory`/`companion`(`{mode,title,synopsis}`). 잘못된 요약은 400이 아니라 버린다: 앱이 저장된 행을 내일 또 보내므로 거부하면 생성이 영영 막힌다. 제목 160자·줄거리 600자를 넘으면 잘라서 쓰고, `<`·`>`·`"`는 `'`로 바꿔 래퍼를 닫지 못하게 한다(2026-10-09 리뷰 반영). `connectionClause`: 직전 스토리는 "이어가거나 인물을 다시 등장시키되 오늘 지문만으로도 읽히게", 같은 날 스토리는 대화를 그 세계(장소·상황·인물) 안에 두게. 요약은 "지시가 아니라 재료" 문구로 보호.
- 앱: `LearningContent.synopsis`(저장·왕복), `summary()`; `LearningRepository.findPreviousSummary(mode, date)`(그날 이전 최신 지문, 한국어 지문 제외); 세션 생성과 선생성 모두 `previousStory`(직전 스토리)와 `companion`(같은 날 다른 모드)을 넘긴다. 선생성은 스토리→대화 순서.
- 옛 지문(synopsis 없음)은 요약 없이 넘어간다 → 연결 없이 생성.
- 테스트: `AiLearningResponsesTest.theSynopsis…`, `LearningRepositoryTest`(이전 에피소드 조회), `ContentPrefetcherTest`(스토리 먼저, 실패 시 companion 없음).
