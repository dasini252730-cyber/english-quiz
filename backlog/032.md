# 032 복습 표현이 있으면 학습 내용 생성이 거의 항상 실패

## 증상 (2026-09-30)
폰: "학습 내용을 불러오지 못했어요. 다시 시도해 주세요." 첫날은 됐고 둘째 날부터 안 됨.

## 원인 (직접 측정)
- `reviewExpressions` 5개를 넘겨 12회 호출 -> 11회 502 `missing_review_expression`. 모델이 복습 표현을 글자 그대로
  못 넣으면 서버가 지문 전체를 버렸다. 저장 표현이 생기는 둘째 날부터 매번 실패하는 구조(031로 자동 등록되면서 더 확실히).
- 1차 수정 후 5/12 `missing_new_expression`: 계약 문구 "exactly 5 entries, plus one more for every supplied review
  expression"을 모델이 "총 5개(복습 포함)"로 읽어 복습 표현만 주석했다.

## 수정 (서버만, 앱 재설치 불필요)
- 복습 표현 누락은 경고 로그로 강등. 퀴즈는 저장 목록의 due 표현을 출제하므로(021) 지문에 없어도 하루를 잃지 않는다.
- `locatePhrase`: `segmentIndex`가 틀린 주석은 다른 세그먼트에서 찾아 위치를 바로잡는다(버리지 않음).
- `callAnthropic`: 출력 계약 위반(세그먼트 수 초과, 새 표현 0 등)일 때만 1회 재시도. 제공자 거절/타임아웃/JSON 오류는
  재시도 안 함. 토큰 추가 비용은 실패한 경우에만.
- `expressionsClause(reviewCount)`: "총 N+5개. N개는 복습 표현(글자 그대로), 5개는 새 표현"으로 숫자를 명시.
- `REVIEW_EXPRESSIONS_WOVEN = 5`: 앱이 최대 12개를 보내도 지문에는 앞 5개만 엮는다. 나머지는 내일도 due.

## 리뷰(code-critic) 반영
- 재시도는 전체 예산 68초 안에서만(2차 시도는 남은 시간 20초 이상일 때, 남은 시간만큼의 타임아웃) - 앱 read timeout
  75초를 넘겨 소켓 타임아웃으로 보이는 일이 없게.
- 재시도 대상은 `OUTPUT_CHECKS` 이름의 오류만(네트워크 오류 등은 재시도 안 함). 모델 텍스트가 JSON이 아니면
  `invalid_model_json`으로 이름 붙여 재시도 대상에 포함.
- 복습 표현이 **전부** 빠진 지문은 계약 위반(재시도 후 502) - 요구사항 18(저장 표현 재등장)의 최소 보증. 일부 누락은 경고.
- 앱의 `MAX_REVIEW_EXPRESSIONS = 12`는 그대로(앱 재설치를 피하려고). 서버가 앞 5개만 엮는다는 점을 앱 주석이 아직
  반영하지 않음 - 다음 앱 변경 때 정리.

## 결과
- 배포 후 복습 표현 5개로 12/12 성공, 지문당 표현 8~10개(복습 5 + 새 3~5). 복습 없이도 12/12.
- 함수 테스트 19/19. 부수 효과: 노란 표현이 늘어 퀴즈 문항도 늘어난다(031과 맞물림).

## 남은 관찰
- `missing_new_expression`은 여전히 실패 사유(재시도 1회 뒤). 계속 나오면 새 표현 0개라도 지문을 내보내는 쪽으로 완화 검토.
