# 019 edge-to-edge 시스템 바 겹침 (실기기)

## 목적
Galaxy S26 실기기 검증(015) 중 발견한, 지원 대상 기기 전체에 영향을 주는 레이아웃 결함을 고친다.

## 증거 (2026-09-26, SM-S942N / Android 16 / API 36)
앱에 window inset 처리가 **전혀 없었다.** `enableEdgeToEdge()` 호출도, `WindowInsets` 사용도 0건이었다.
`targetSdk 37` 이라 Android 15+ 는 edge-to-edge 를 강제하므로 모든 화면이 시스템 바 아래에 그려졌다.

실측값:
```
앱 윈도우        1080 x 2340  (전체 화면, inset 소비 0)
statusBars       [0,0][1080,111]      = 42dp
navigationBars   [0,2214][1080,2340]  = 48dp
```

- 홈 헤더는 top padding 28dp(=73px)에서 시작해 상태바 안쪽 38px 에 그려졌다.
- Reader 화면이 가장 심했다. 뒤로가기 버튼과 `Conversation` 타이틀이 상태바 텍스트와 겹치고,
  우측 전체재생 버튼이 배터리 아이콘 위에 올라갔다.
- 하단 `다음 단계: 퀴즈` 버튼이 내비게이션 바 **아래로** 들어가 3버튼이 그 위에 겹쳤다.
  버튼 하단을 누르면 내비게이션 바가 탭을 가로챈다. 단순 미관 문제가 아니라 조작 불가 구간이다.

에뮬레이터(Medium_Phone_API_36.1, 같은 API 36)에서는 상태바가 낮아 드러나지 않았다. 이 결함은
실기기 주행에서만 나왔고, 015 를 실기기로 해야 하는 이유를 그대로 보여 준다.

## 수정
신규 `app/src/main/kotlin/com/englishquiz/app/ui/theme/MongleInsets.kt`
- `Modifier.mongleScreenInsets()` = `windowInsetsPadding(WindowInsets.safeDrawing)`.
  배경 뒤·스크롤 앞에 두어 배경색은 화면 끝까지 가고 콘텐츠만 밀린다.
- `Modifier.mongleBottomSheetInsets()` = `windowInsetsPadding(WindowInsets.navigationBars)`.
  하단에 붙는 시트는 내비게이션 바만 비키면 된다.
- `DarkBackgroundSystemBars()` — 결과 화면처럼 어두운 배경이 바 밑까지 차는 화면에서 바 아이콘을
  흰색으로 바꾸고 나갈 때 되돌린다.

적용 위치
- `MainActivity.kt` — `enableEdgeToEdge(statusBarStyle/navigationBarStyle = SystemBarStyle.light(TRANSPARENT, TRANSPARENT))`.
  투명 스크림이라 화면 자체 배경이 바 밑까지 이어지고, `light` 가 크림 캔버스에 필요한 어두운
  아이콘을 유지한다. 테마의 `windowLightStatusBar` 는 Android 15+ 에서 무시된다.
- 화면 루트 8곳: `HomeScreen`, `AssessmentScreen`, `ResultScreen`, `QuizScreen`, `ReaderScreen`,
  `ReviewScreen`, `SessionStatusScreen`, `EnglishQuizApp.CenteredMessage`.
- `MeaningOverlay` 바텀시트.
- `ResultScreen` 은 보라 배경이라 `DarkBackgroundSystemBars()` 를 함께 건다.

## 완료 기준
- Galaxy S26 에서 모든 화면의 헤더가 상태바를 비키고, 하단 버튼이 내비게이션 바를 비킨다. **확인함.**
- 세로/가로 양쪽에서 성립한다. **확인함** (가로에서는 내비게이션 바가 오른쪽으로 가는데 `safeDrawing` 이 처리).
- 글자 크기 1.3 에서도 성립한다. **확인함.**
- `lint`, `assembleDebug`, JVM 단위, 계측이 통과한다. **확인함** — lint 통과, 단위 59건,
  계측 80건(에뮬레이터), 계측 80건(실기기 SM-S942N).

## 남은 것
이 변경을 증명하는 자동 테스트가 없다. 화면 스크린샷으로만 확인했다. 계측으로 고정할 방법을
`code-critic` 에 물어 두었고, 방법이 있으면 테스트를 추가한 뒤 `done` 으로 옮긴다.

## 2026-09-26 리뷰 반영과 마감
`code-critic` 리뷰에서 나온 세 가지를 반영했다.

1. **놓친 화면 1곳** — `HomeRoute.kt` 의 홈 요약 로드 실패 화면(`저장한 학습 정보를 불러오지 못했어요.`)에
   inset 이 없었다. 같은 방식으로 `mongleScreenInsets()` 를 붙였다. 리뷰어가 `background(MongleColor` 로
   전체 루트를 훑어 확인한 마지막 미적용 루트다.
2. **`DarkBackgroundSystemBars` 복원값** — 나갈 때 "밝은 바" 를 하드코딩해 되돌리던 것을, 진입 시
   `controller.systemBarsAppearance` 를 저장했다가 그대로 되돌리도록 바꿨다. 어두운 화면이 겹칠 때
   안쪽 화면이 아이콘을 잘못 되돌리는 경로를 막는다.
3. **증명하는 테스트 추가** — `SystemBarInsetsTest.readerKeepsItsHeaderAndBottomButtonClearOfTheSystemBars`.
   호스트 액티비티 윈도우에서 실제 `systemBars` inset 을 읽어, Reader 의 전체재생 버튼 top 이 상태바
   아래에 있고 `다음 단계: 퀴즈` 버튼 bottom 이 내비게이션 바 위에 있는지 단정한다.
   **수정을 일시적으로 되돌리고 돌려 실제로 실패하는 것을 확인했다**
   (`header top 8.0.dp is under the 24.0.dp status bar`). 되돌린 뒤 통과.

리뷰어가 문제 없다고 판정한 것: `enableEdgeToEdge` 를 `super.onCreate` 앞에서 호출하는 순서, 플랫폼
`insetsController` 사용(minSdk 34 라 가드 불필요), `safeDrawing` 의 IME 포함(앱에 TextField 0건),
modifier 순서, 가로 모드 측면 내비바 처리, `themes.xml` 의 죽은 `statusBarColor`(동작 차이 없음).

### 최종 검사
- `lint` 통과, JVM 단위 59건 통과, `assembleDebug` 통과
- 계측 **81건** 통과 — 에뮬레이터(API 36) 와 실기기(SM-S942N) 양쪽
- 실기기 계측 첫 시도는 46건, 두 번째는 13건이 `No compose hierarchies found` 로 실패했는데, 폰이
  `Dozing`/잠금 상태라 액티비티가 뜨지 못한 환경 문제였다. 깨우고 잠금을 푼 뒤 81/81. 코드 문제 아님.

완료 기준을 모두 충족해 `done` 으로 옮긴다.
